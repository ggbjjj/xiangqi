数据库表：sources（来源/授权声明）、source_files（原始文件 BLOB/校验和）、raw_records（逐局原始记录、状态与错误）、decoded_records（CBL 解码版本、原始起始 FEN、主线、原始胜负、元数据与校验错误）、games（真实起始 FEN、完整动作 JSON 数组、总步数、胜负、划分）、metadata（编码与校验口径）。每局一个 games 样本，初始局面允许为残局或黑方先走。

CCPD 58,468 条原始棋谱中：53,607 条记录映射到 27,759 局有效样本；77 条为空或文本结构未通过，另 1 条走法校验失败；其余 4,783 条电脑对局或其他题型保留原文、排除本轮大师棋谱预训练。

2026-10-28 完成 CNVCS CBL v21 主线解码：3,389 条中 3,362 条合法，去重为 3,170 局；其中 617 局已在 CCPD 样本中，新增 2,553 局（训练 2,263 / 验证 136 / 测试 154）。17 条空谱标为 excluded_empty，10 条非法主线标为 rejected，不保留错误前缀作训练。变着与注释完整保留在原始字节中；训练选取深度优先存储的第一条主线。

原始 CBL 结果为红胜 1,449、黑胜 380、和棋 1,085、未知 475；合格原始记录的结果为红胜 1,441、黑胜 379、和棋 1,076、未知 466。结果按来源原样保存在 decoded_records；games.result 使用 1-0 / 0-1 / 1/2-1/2 / *。同局已知胜负冲突的 4 局标记 result_conflict，合并结果设为 *，仅训练策略，保留全部来源结果待核对。另从 CBL 补全了原库 2 局未知结果。详见 [import_report.json](import_report.json) 和 [cbl_merge_report.json](cbl_merge_report.json)。

本次统计图、SVG、逐谱统计和完整性检查位于本地 artifacts/cbl-merge-20261028；合并前数据库备份位于 backups/datasets/cbl-before-20261028-235428-661510/dataset.sqlite3。与备份对比，原始文件与逐局原文没有改变，已有棋局走法、起始局面、划分均保留，没有 split_group 跨集合。

去重依据为规范初始局面与完整动作序列。相同初始局面及前 24 步组成 split_group，按稳定哈希约 90%/5%/5% 划分；该组不会跨集合。短于 24 步采用全部动作。仍可能存在跨集合共享开局或不同长度的同局摘录，指标应理解为棋谱预测能力，不能宣称棋力等级。

入库校验逐步检查棋子规则、己方将帅安全与轮到谁走；不套用桌面游戏的三次重复/120步不吃子自动结束条件，也不执行正式比赛长将长捉裁决。错误整局隔离，绝不静默保留错误前缀。

数据库保留 K 个完整动作；读取层按 T 产生 `ceil(K/T)` 个连续片段，覆盖完整主线，尾段不足 T 补零，不跳步压缩、不改写源库。100 步、T=32 得到四段，有效长度为 32、32、32、4。每段恢复原局对应步的棋盘、走棋方与完整规则历史，神经网络从当前片段重新建立缓存；各段继承原始终局结果，按实际走方生成胜/和/负标签。输入填充为全 0，动作及价值标签为 -100，合法与来源掩码为 False；损失只按各段有效长度计数。

训练、验证和测试均先选择原始划分及原始棋局上限，再完整分段，同局片段不会跨划分。GameDataset.ids 保留原始棋局编号，len(dataset) 为片段数，dataset.segments 保存原局编号及起止单步偏移；read_segment() 还返回真实 start_fen、result 和 start_ply。iter_game_batches 返回各片段有效 lengths。若出现当前规则禁止的重复走法，只保留其之前的合法策略前缀；后续片段有效长度可为 0，该局所有片段的价值标签均忽略。

X_t 是执行 a_t 前的局面；最终无后续动作的终局不额外作标签。编码：红黑绝对位置 14 通道 + 红走=1/黑走=0 的第 15 通道；方格号 9*r+c，动作号 90*src+dst。

重建/断点导入：`python -m data_pipeline.import_records --workers 4`，现在会自动解码并合并待处理 CBL。再次运行跳过已入库文件和已校验记录。来源文件位于 pretrain_data/source_survey_20261024。

已有数据库可单独运行 `python -m data_pipeline.merge_cbl`：直接读取 raw_records 中的原始 CBL，无需再次下载；合并前自动备份，默认生成 JSON、Markdown、PNG 和 SVG。可选 `--db 路径`、`--output 报告目录`；`--no-plot` 可在未安装 matplotlib 的数据导入环境只生成文字报告。每个解码版本只处理一次；`--reprocess` 显式重解码时仍按棋局身份去重。

## 独立残局库

`endgames.sqlite3` 单独保存 CNVCS 残局栏目 14 套 CBL 与本地 CCPD `Dataset/殘局/` 的 244 条 PGN，不改写 `dataset.sqlite3`。训练通过 `--book-source main`（默认主库）、`endgames`（仅残局）或 `both`（两库合读）选择范围；三种方式共用同一个读取函数。

| 内容 | 数量 |
|---|---:|
| 原始记录 | 2,779 |
| 合法非空主线（含重复） | 2,760 |
| 去重后有效残局 | 2,246 |
| 空谱 / 错误记录，隔离保留 | 12 / 7 |
| 红胜 / 黑胜 / 和棋 / 未知 | 1,119 / 105 / 440 / 582 |
| 训练 / 验证 / 测试划分 | 2,013 / 112 / 121 |
| 最短 / 最长 / 平均 / 中位步数 | 1 / 135 / 25.81 / 21 |

CNVCS 去重后 2,003 局、CCPD 244 局，两来源重复 1 局，合计 2,246 局。另有 12 局与原棋谱库完全重合，保留并在 `games.metadata_json.overlaps_book_database` 中标记；扣除这 12 局，新增独有残局为 2,234 局。合读读取器会自动去掉这 12 局重复，保留主库棋局及划分；相同 split_group 的残局也沿用主库划分，均不改写原 SQLite。不同长度摘录、镜像或前 24 步不同的分支不按精确重复合并。

表结构与现有棋谱库兼容：`source_files` 保存全部原始 CBL 文件及 244 份 PGN，`raw_records` 保存逐局原文及状态，`decoded_records` 保存原始胜负、解码主线、元数据与错误，`games` 只保存去重后的合法完整主线。分支和注释保留在原始字节中。未知胜负保持 `*`，不会当作和棋；若已知胜负冲突，合并结果同样设为 `*` 并标记，原始结果仍可追溯。

本地原始文件齐全时执行 `python -m data_pipeline.import_endgames` 重建，已有该工具管理的残局库会先备份再替换。该命令只读原棋谱库，禁止目标路径覆盖原棋谱库。原始 CBL 和清单位于 `pretrain_data/endgame_survey_20261029/`；上传 AutoDL 时直接传输构建好的 `Data/endgames.sqlite3` 即可，不需要原始文件。

仅更新统计与图片：`python -m data_pipeline.import_endgames --report-only`。可选 `--db 路径`、`--output 报告目录`、`--bin-width 16`、`--no-plot`。机器统计位于 `Data/endgames_report.json`；PNG、SVG、统计 JSON 与 Markdown 位于本地 `artifacts/endgames-20261029/`。

统一读取接口示例：`GameDataset(T=32, source='both', db=DATA_DB, endgame_db=ENDGAME_DB)`；`BookDataset` 与 `iter_game_batches` 接受相同的 `source` 和 `endgame_db`，旧参数顺序及返回格式保持兼容。读取顺序为来源选择与跨库去重 → 划分 → 原局 limit → T 连续分段与补零。合读结果冲突则价值标签为未知，非冲突已知结果可补全同局未知标签。`dataset.summary` 包含方式、实际路径、各库局数/片段数、重复数和冲突数。

当前三种方式在 T=32 下的训练原局/片段为 main 27,179/82,225、endgames 2,013/2,640、both 29,181/84,853。合读验证集为 1,687 局/4,830 段，测试集 1,678 局/4,907 段。命令详见 [指令.md](../指令.md)。
