# 混合训练与自弈接口

当前 AutoDL 命令、按 ID 自动选参、累计轮数与中断保存规则，以项目根目录 [指令.md](../指令.md) 为统一使用入口。

实现依据为提供的《混合训练损失函数与探索策略》：

`L = λ_book L_book + λ_ppo L_PPO + λ_value L_value - λ_entropy H`

所有权重非负，不要求相加为 1；为 0 的项直接跳过并隐藏对应曲线。`--lambda-policy`（兼容别名 `--lambda-book`）、`--lambda-value`、`--lambda-ppo`、`--lambda-entropy` 分别控制策略、价值、PPO、动作熵。棋谱动作 CE 使用合法动作上的原始策略；自弈 PPO 与熵使用温度和均匀探索混合后的实际行为分布。开启古谱熵正则时，使用古谱局面原始合法动作分布。自弈动作不作为棋谱正确标签。

## 共用损失接口

代码在 `training/loss.py`，两个网络都可调用：

```python
from training.loss import LossBatch, LossWeights, mixed_loss

# 仅古谱下一手标签，actions 是 [T,B] int64，legal 是 [T,B,8100] bool。
batch = LossBatch.books(actions, legal, lengths)
result = mixed_loss(output, batch, LossWeights(book=1, ppo=0, value=0, entropy=0))
result.total.backward()
```

`output` 可以是 HaiKu 的策略 logits 张量，也可以是含 `policy_logits`、`value_logits` 的 Opus 输出对象。价值输出为未做 Softmax 的三个 logits，顺序是当前走方胜、和、负。缺少价值头且有效价值样本存在时，启用价值损失会明确报错。

自弈或混合数据使用 `LossBatch` 的以下字段：

| 字段 | 说明 |
|---|---|
| actions、legal、lengths | 实际动作、重放得到的合法掩码、每个样本的有效长度；自弈样本为 C 步片段 |
| book_mask | 参加棋谱下一手监督的步，不能与 selfplay_mask 重叠 |
| selfplay_mask | 片段内的新生成动作；填充为 False，暖启动前缀只用于 CPU 重放 |
| value_targets | `[T,B]` int64，当前方胜/和/负=0/1/2，未知=-100；None 表示全部缺少价值标签 |
| value_mask | 可选价值监督范围，默认棋谱与自弈的有效来源步 |
| old_log_mu、old_value | 采样时实际动作的旧 log μ、旧标量价值，均固定不求梯度 |
| temperature、epsilon | 采样时参数，可为标量或 `[T,B]` |

PPO 优势为 `z - old_value`，其中 z 为终局胜 +1、和 0、负 -1；概率比为 `exp(log_mu_new - old_log_mu)`，裁剪宽度默认 0.2。两次 μ 使用相同温度和 epsilon。熵对当前全部合法动作计算，保留梯度；未知结果自弈步不参加 PPO、价值或自弈熵平均。无结果古谱仍可参加策略监督及显式启用的古谱熵正则。

| 默认场景 | λ_policy（λ_book） | λ_value | λ_ppo | λ_entropy |
|---|---:|---:|---:|---:|
| Opus 古谱 | 1 | 1 | 0 | 0 |
| Opus 自弈 | 1 | 1 | 1 | 1 |
| Opus 混合 | 1 | 1 | 1 | 1 |
| HaiKu 古谱 | 1 | 0 | 0 | 0 |
| HaiKu 自弈/混合 | 1 | 0 | 1 | 1 |

HaiKu 当前没有价值头，默认价值权重为 0；显式传入非零价值系数会报错。生成时记录 `has_value_head=0`，使用固定零基线 `old_value=0`。Opus 使用价值头的 `P胜-P负` 作为旧基线。古谱加载器读取原始 `result`，按当前走棋方转换为 W/D/L=0/1/2，裁剪不改变原始结果，填充与未知结果为 -100。无结果古谱的策略仍参与训练，价值项自动忽略。纯自弈没有古谱策略监督样本，所以策略交叉熵项虽默认系数为 1，实际贡献为 0。

当 λ_value > 0 而胜负未知时，该步价值损失仍严格为 0。`NULL`、空串、纯空白或 `*` 均读取成 `-100`，接口也接受 `value_targets=None`。只选择已知标签且处于有效长度/价值掩码内的步计算交叉熵，并仅以这些步的数量作为价值平均分母。一个微批或 TBPTT 段没有已知标签时，即使整个逻辑批量有价值监督，其价值损失和仍为 0；整批未知时不计算价值交叉熵，也不连接价值独有分支的梯度，AdamW 的已有动量与权重衰减不会更新这些参数。仅开启价值项且整批未知时，整个优化器更新跳过。直接调用 `models.Opus.loss.masked_value_ce` 时，None 或全 `-100` 返回可反向传播的全零损失，不读取未知位置的 logits。

`result.sums`、`result.counts` 返回各项未平均损失和有效样本数；`diagnostics` 返回概率比、裁剪计数与近似 KL 的和。分段与微批量时，先在整个逻辑批量相加 `batch.counts()`，通过 `denominators=whole_batch_counts` 传给每段。不能将 16 步和 4 步两段各自求平均后直接相加。

## 指定版本生成自弈

在项目根目录运行；下面统一使用已安装依赖的项目 Python，也可在命令前使用 `uv run --locked --extra cpu`，远程 GPU 改为 `--extra gpu`。

```powershell
python model_store.py --family Opus list-versions
python -m selfplay --family Opus --version "Opus-5.initial" --games 1000 --max-plies 1000 --temperature 1.2 --epsilon 0.02 --device cuda
python -m selfplay --family HaiKu --version "HaiKu-5.1" --games 1000 --max-plies 1000 --temperature 1.2 --epsilon 0.02 --device cuda
```

CPU 使用 `--device cpu`。这些是调用示例，开发过程中没有替用户执行 1000 局正式生成或长时间训练。

必须传 `--family`；可用 `--id ID2`、`--version` 或 `--latest` 指定采样参数，省略选择器时解析本模型后台默认 ID。先解析一次，冻结该参数快照控制红黑双方。输出包含版本名、参数 ID、累计实际轮数、权重 SHA-256 和 run_id；生成期间后台切换默认或发布名称不会改变本批模型。Opus-5.initial 仍是未训练初始化，生成数据不代表已有棋力。

探索分布为 `(1-ε) Softmax(legal_logits/τ) + ε/合法动作数`，非法动作严格为 0。默认温度 1.2、epsilon 0.02；设置 `--temperature 1 --epsilon 0` 可只按原策略概率采样。

程序接口：

```python
from selfplay.generator import SelfPlayGenerator, SelfPlayRules
from training.exploration import Exploration

generator = SelfPlayGenerator.from_version(
    'Opus', 'Opus-5.initial',
    exploration=Exploration(temperature=1.2, epsilon=0.02),
    rules=SelfPlayRules(max_plies=1000), device='cpu', seed=42)
report = generator.generate(games=10, micro_batch=8, save_every=16)  # report['run_id'] 用于后续训练
```

`generate` 还接受 start_fen、prefix（动作 ID 序列）、cancel_event、progress、on_step。progress 在完整对局结束时收到完成/已保存/缓冲局数；on_step 在每次批量前向及暖启动后收到实际生成步数、推理批次数、有效并行局数，可接自定义进度展示。生成时前缀完整重放以恢复缓存和规则历史；前缀不参与损失。CLI 对应 `--start-fen` 和 `--prefix-json 路径`，后者必须是有序动作 ID 的 JSON 数组。裁剪训练在 CPU 重放完整前缀及片段前的动作，恢复片段起始棋盘、走棋方与规则历史；模型只接收当前片段，重建本片段的 KV 缓存。

`micro_batch` 为同时推理的局数，必须为 2 的幂且整除 save_every；不指定时自动选不超过 16 的最大可用值。模型前向与探索概率计算在指定设备上按批处理，棋盘规则和逐局抽样在 CPU 上完成。每批结束后重建下一批缓存，每局使用独立随机数状态；提前结束的槽位以 valid=False 屏蔽，不与其他棋局混用历史。CLI 的进度、预计时长、结束时刻、吞吐和 GPU 利用率/显存占比默认每秒刷新，参数见 [指令.md](../指令.md)。

同一状态与走方在同一循环中连续第三次出现时，下一走方必须变招：屏蔽继续该循环的历史下一手，其他合法动作正常采样。仅零散累计出现三次、两段循环不同，不触发；中途变招后重新判定连续循环。初始局面计第一次，阈值可用 `--repetition` 设置，默认 3。该规则不区分长将长捉责任，适用于红黑双方；重复本身不判和。

先依据包含重复变招限制的掩码判断有无合法动作，无动作时判当前方负；若棋子几何走法存在而被变招限制排空，终局原因记为 `no_legal_alternative`。随后判断双方无进攻子力、连续未吃子及总步数上限和棋。默认连续未吃子 120 单步、总生成上限 1000 单步；红黑合计，max-plies 只统计本次新生成部分。资源/取消中断时丢弃未提交批次与未完成棋局。这些是项目自定义对局规则，不实现赛事长将长捉责任裁决。

新 run 的 `rules_json.repetition_policy` 为 `consecutive-cycle-force-change-v1`。训练重放恢复完整规则历史，重新生成采样时的掩码，历史不随网络 K/V 滑动窗口裁掉。没有版本字段的旧 run 使用原来的几何掩码，保留 PPO 原采样分布；未知规则版本拒绝读取。古谱仅保留当前规则允许的策略前缀；后续出现禁止循环，或原棋谱在须变招局面结束时，该局价值标签设为未知，不改写源数据库。

## 自弈 SQLite

```text
Data/dataset.sqlite3                    原古谱库
Data/endgames.sqlite3                   独立残局库
Data/SelfPlay/HaiKu/games.sqlite3        所有 HaiKu 版本的自弈数据
Data/SelfPlay/Opus/games.sqlite3         所有 Opus 版本的自弈数据
ModelParameters/HaiKu/models.sqlite3    HaiKu 参数库
ModelParameters/Opus/models.sqlite3     Opus 参数库
```

只按模型系列分库，不按版本建文件夹或文件。`--data-db` 可显式指定其他自弈库，但不能混写模型系列，也不能写入古谱库或参数库。

| 表 | 内容 |
|---|---|
| metadata | 模型系列与库结构版本 |
| runs | 每批采样的模型版本、参数 ID、权重校验值、网络配置、探索配置、规则、随机种子、价值头标记、微批量、设备 |
| games | 初始 FEN、暖启动前缀、有序新动作、结果、结束原因、最终 FEN、步数、生成序号（从 0 开始，对应 seed+序号） |
| steps | 每步走方、动作、旧 log μ、旧价值、当时温度和 epsilon |

默认每 K=16 局完整对局及其逐步记录在一个事务内提交，`--save-every` 可调整。中断时只保留已提交批次，当前不足 K 局的缓冲全部丢弃；正常完成总局数时保存最后不足 K 局的尾批。无需保存大量 8100 维 one-hot 或旧 KV 缓存；训练从初始局面与动作恢复输入。历史库若有未知结果样本，其步仍不参加终局回报损失。

## 自弈和混合训练入口

生成完成后，使用返回的 run_id 和同一个起始模型版本，替换下面的“实际run_id”。PPO 不默认读取库中全部历史版本。

```powershell
# 只训练本轮 Opus 自弈，策略/价值/PPO/动作熵系数默认 1/1/1/1
python -m training --family Opus --version "Opus-5.initial" --source selfplay --rollout-run 实际run_id --C 128 --epochs 2 --batch-size 8 --micro-batch 1 --tbptt-steps 16 --device cuda

# 古谱和本轮自弈混合，显式给四个权重
python -m training --family Opus --version "Opus-5.initial" --source mixed --rollout-run 实际run_id --T 128 --C 128 --book-limit 128 --lambda-book 0.1 --lambda-ppo 1 --lambda-value 1 --lambda-entropy 0.01 --epochs 2 --device cuda

# HaiKu 自动关闭价值项，策略/价值/PPO/动作熵系数为 1/0/1/1
python -m training --family HaiKu --version "HaiKu-5.1" --source selfplay --rollout-run 实际run_id --C 128 --epochs 2 --device cuda

# Opus 古谱同时监督策略与价值，策略/价值/PPO/动作熵系数默认 1/1/0/0
python -m training --family Opus --version "Opus-5.initial" --source books --book-limit 128 --epochs 1 --device cuda
```

`--version` 是本轮学习的起始权重，必须与 rollout-run 的采样参数 ID 和 SHA-256 一致；同一批近期数据可进行显式指定次数的 PPO 更新。下一轮请指定新训练得到的参数 ID，重新生成新对局。该入口新建 AdamW 优化器，不是原 train.py 的优化器续训入口；原 HaiKu 续训仍使用 resume_train.py。

古谱训练在 `data_pipeline.loader.GameDataset` 中按 `--T`（默认 120）把完整棋局连续分段，`BookDataset`、`iter_game_batches` 与旧 train.py 共用该逻辑。100 步、T=32 产生 4 段，lengths 为 `[32,32,32,4]`，尾段补零 28 步。验证和测试使用独立的 `--L 32`，不跟随 T；三者沿用原局划分，原局 limit 后保留全部切片。原始局面可以非标准，段前动作在 CPU 重放以恢复棋盘、走方和规则历史，模型缓存从当前片段起点建立。

自弈使用独立的 `--C`（默认 128），在读取原库时把全部新生成动作连续分段：512 步产生 4 个 128 步样本；530 步产生 4 个完整片段和一个有效 18 步、补零 110 步的尾段；不足 C 步也保留一个样本。两种分段每个有效动作恰好出现一次，不额外产生空尾段；原 SQLite 不改写。可选 `--max-selfplay-plies` 先限制每局读取的新生成步数，再分段，默认不限制。

每段从原局对应步的棋盘与真实走棋方开始，允许非标准开局。完整暖启动前缀与该段之前的动作在 CPU 重放，恢复完整重复变招历史，不占 C、不参与该片段损失。每段有独立模型 KV 缓存，模型时间索引从 0 开始；裁剪改变了模型的历史上下文，同一参数下的 PPO 新旧概率不保证完全相等。旧 log μ、旧价值、温度和 epsilon 仍使用原局对应动作的原始记录，不改写为裁剪后的新测量。

各段继承原局相同的终局结果，逐步按真实走棋方转换为 W/D/L；奇数 T/C、执黑开始和中途棋盘均适用。输入补零、合法掩码与来源掩码置 False、动作和价值标签填 -100，真实长度独立记录；填充不参加任何损失或分母。混合微批按 `max(T,C)` 补齐，各样本有效长度保持不变。一个 epoch 遍历全部片段，逻辑批量与微批量均按片段数计数。古谱的规则冲突使策略只保留第一次禁止走法之前的前缀；后续片段有效长度可为 0，仍不产生损失，并忽略整局价值标签。

Python 读取示例：

```python
from training.data import BookDataset, SelfPlayDataset

books = BookDataset(T=32, db='Data/dataset.sqlite3')
print(len(books.ids), len(books))  # 原始古谱数、分段后的样本数
book = books[1]                 # 真实 start_fen / result / source_game_id / start_ply

dataset = SelfPlayDataset('Data/SelfPlay/Opus/games.sqlite3', run_id, family='Opus', C=128)
print(len(dataset.ids), len(dataset))  # 原始完整对局数、裁剪后的样本数
sample = dataset[0]
# sample.x: [128,15,10,9]，length 为有效步数；start_fen 为该段真实起点。
# result 为原局结果，source_game_id / start_ply 可追溯原局和新生成动作偏移。
```

终端新增“本次训练总局数（切段后）”。配置、启动日志分别保存 book_games / book_segments、selfplay_games / selfplay_segments、training_samples，以及原始验证局数与验证片段数；检查点 training_state 保存 T、C 和 book_crop_version。训练默认微批量为 16，省略参数选择器时自动加载实际轮数最多的 ID。旧 train.py 优化器续训遇到旧读取语义时，按新分段验证重新选择 best。

`training.engine.train_logical_batch` 是共用程序接口，接收模型、优化器、多个 `TrainingBatch` 微批量和 LossWeights，预先汇总各项整批分母。默认每 16 步 backward 后 detach 缓存，整个逻辑批量只更新一次。没有有效 PPO 损失时使用 `train()` 启用残差 Dropout；当 `weights.ppo > 0` 且逻辑批量中存在有效 PPO 样本时，整个逻辑批量使用 `eval()` 前向但保留梯度，关闭 Dropout 以保持与采样模式一致的概率计算。API 的 PPO 调用还必须明确传 behavior_checkpoint_id 和 behavior_sha256，数据来源必须匹配。

每次 `iter_chunks` 调用以 `cache=None` 开始，同一微批量的反传段保留 K/V（只 detach 计算图），下一微批量无论 B 是否相同均新建缓存、时间归零；逻辑批量的梯度累积不会跨微批量传递 K/V。HaiKu 新模型与古谱 CLI 默认窗口改为 30，`--context-plies` 可覆盖并保存；Opus 五个窗口保持不变。旧检查点保留原配置，自弈/混合默认跟随采样检查点，PPO CLI 拒绝与采样窗口不一致的覆盖。

两种模型每核心五个 Block、每 Block 的注意力与 FFN 分支各一个 Dropout，共 10 个；HaiKu 共 30 个，Opus 共 50 个。默认 `p=0.1`，`--dropout` 覆盖并写入网络配置；旧权重严格兼容，旧配置缺失该字段时采用 0.1。验证和生成器均关闭 Dropout。详见 [网络图](diagrams/README.md) 与 [训练参数](../指令.md)。

棋谱训练与混合训练的棋谱部分均支持 `--book-source main|endgames|both`，分别读取主棋谱库、独立残局库、两库合读。路径为 `--book-db` 和 `--endgame-db`。三种方式都在 `GameDataset(..., source=..., endgame_db=...)` 内处理，经 `BookDataset` 或 `iter_game_batches` 输出同一格式，裁剪 T、补零、lengths、未知胜负的价值掩蔽保持一致。验证集使用同一来源方式的 validation 划分。合读先跨库去重并协调相同 split_group，再划分、原局 limit 与切段；重复局核对起始 FEN/完整动作并沿用主库划分，冲突胜负不参与价值监督。终端、config.json、评估结果和检查点都记录实际读取方式与来源统计。完整三条命令见 [指令.md](../指令.md#三种棋谱加载命令)。

训练接口可传 `progress=callback`，每个梯度截断段后回调该微批的完成比例、有效步数、微批内累计损失及分项；回调不改变损失分母或参数更新频率。返回结果另含 duration_seconds、micro_batches、micro_batches_per_second。默认 CLI 使用共用的 `training.progress.ConsoleProgress` 展示这些信息和独立刷新的 GPU 监控。

训练保存为对应模型系列库中的新参数版本，不覆盖旧权重，不自动改公开模型名称。`--set-default` 可显式更新默认指针；`--description` 添加版本说明；`--smoke` 版本不能发布到游戏。日志在 `runs/mixed/` 下，记录四项损失、有效样本数、概率比、裁剪比例、近似 KL 和更新状态，同时记录 TensorBoard 事件供中文实时窗口读取。古谱或混合训练存在独立 validation 划分时，按完整验证集的平均切片困惑度选择 best，并写入 best.json；开启 --set-default 时只更新到该 best。自弈不按 PPO 损失或采样胜率选择棋力最佳；固定对手评估尚未加入。窗口与 get-best 命令见 [指令.md](../指令.md)。

验证使用 `training.evaluation.evaluate_books(model, dataset, ngram=16, ...)`，dataset 由同一读取器按 L（默认 32）切片，支持 GameDataset / BookDataset。每片 PPL 为 `exp((真实步 NLL 之和 + 填充步数*ln2)/L)`，以合法动作概率计算，不计算 top-1/top-3。n 为最多输入局面数（含当前），须不大于 L；逐步滑动窗口并重建状态，真实动作只计一次。填充步不前向计算，评分概率固定 0.5。一个切片恰有一个 PPL，零有效长度片段为 2；每轮持久化全部逐片 JSONL 和区间 PNG/SVG，并在终端输出验证原局数、切片数。`validation/latest.json` 供中文窗口显示最新完整分布。详见 [验证说明与独立评估命令](../指令.md#验证切片序列困惑度与区间图)。
