# 混合训练与自弈接口

当前 AutoDL 命令、按 ID 自动选参、累计轮数与中断保存规则，以项目根目录 [指令.md](../指令.md) 为统一使用入口。

实现依据为提供的《混合训练损失函数与探索策略》：

`L = λ_book L_book + λ_ppo L_PPO + λ_value L_value - λ_entropy H`

所有权重非负，不要求相加为 1；为 0 的项直接跳过。棋谱动作 CE 使用合法动作上的原始策略；PPO 与熵使用温度和均匀探索混合后的实际行为分布。自弈动作不作为棋谱正确标签。

## 共用损失接口

代码在 `training/loss.py`，两个网络都可调用：

```python
from training.loss import LossBatch, LossWeights, mixed_loss

# 仅古谱下一手标签，actions 是 [T,B] int64，legal 是 [T,B,8100] bool。
batch = LossBatch.books(actions, legal, lengths)
result = mixed_loss(output, batch, LossWeights(book=1, ppo=0, value=0, entropy=0))
result.total.backward()
```

`output` 可以是 HaiKu 的策略 logits 张量，也可以是含 `policy_logits`、`value_logits` 的 Opus 输出对象。价值输出为未做 Softmax 的三个 logits，顺序是当前走方胜、和、负。缺少价值头且有效价值样本存在时，启用价值损失会明确报错。

自弈或混合数据使用 `LossBatch` 的以下字段：

| 字段 | 说明 |
|---|---|
| actions、legal、lengths | 实际动作、重放得到的合法掩码、每局有效长度 |
| book_mask | 参加棋谱下一手监督的步，不能与 selfplay_mask 重叠 |
| selfplay_mask | 新生成的步；暖启动前缀、填充为 False |
| value_targets | `[T,B]` int64，当前方胜/和/负=0/1/2，未知=-100 |
| value_mask | 可选价值监督范围，默认棋谱与自弈的有效来源步 |
| old_log_mu、old_value | 采样时实际动作的旧 log μ、旧标量价值，均固定不求梯度 |
| temperature、epsilon | 采样时参数，可为标量或 `[T,B]` |

PPO 优势为 `z - old_value`，其中 z 为终局胜 +1、和 0、负 -1；概率比为 `exp(log_mu_new - old_log_mu)`，裁剪宽度默认 0.2。两次 μ 使用相同温度和 epsilon。熵对当前全部合法动作计算，保留梯度；未知结果不参加本方案的 PPO、价值或熵平均。

| 场景 | λ_book | λ_ppo | λ_value | λ_entropy |
|---|---:|---:|---:|---:|
| 仅下一手古谱 | 1 | 0 | 0 | 0 |
| 有真实结果的古谱 | 1 | 0 | 1 | 0 |
| Opus 自弈 | 0 | 1 | 1 | 0.01 |
| Opus 混合 | 0.1 | 1 | 1 | 0.01 |
| HaiKu 自弈 | 0 | 1 | 0 | 0.01 |

HaiKu 当前没有价值头；生成时显式记录 `has_value_head=0`，使用固定零基线 `old_value=0` 计算蒙特卡洛优势，不伪造 WDL 预测。其价值权重设为 0。Opus 使用价值头的 `P胜-P负` 作为旧基线。当前古谱加载器仍只提供下一手标签；未来有可靠结果时可直接传入 value_targets。

`result.sums`、`result.counts` 返回各项未平均损失和有效样本数；`diagnostics` 返回概率比、裁剪计数与近似 KL 的和。分段与微批量时，先在整个逻辑批量相加 `batch.counts()`，通过 `denominators=whole_batch_counts` 传给每段。不能将 16 步和 4 步两段各自求平均后直接相加。

## 指定版本生成自弈

在项目根目录运行；下面统一使用已安装依赖的项目 Python，也可在命令前使用 `uv run --locked --extra cpu`，远程 GPU 改为 `--extra gpu`。

```powershell
python model_store.py --family Opus list-versions
python -m selfplay --family Opus --version "Opus-5.initial" --games 1000 --max-plies 1000 --temperature 1.2 --epsilon 0.02 --device cuda
python -m selfplay --family HaiKu --version "HaiKu-5.1" --games 1000 --max-plies 1000 --temperature 1.2 --epsilon 0.02 --device cuda
```

CPU 使用 `--device cpu`。这些是调用示例，开发过程中没有替用户执行 1000 局正式生成或长时间训练。

必须传 `--family`；可用 `--id ID2`、`--version` 或 `--latest` 指定采样参数，省略选择器时解析本模型后台默认 ID。先解析一次，冻结该参数快照控制红黑双方。输出包含版本名、参数 ID、累计实际轮数、权重 SHA-256 和 run_id；生成期间后台切换默认或发布名称不会改变本批模型。Opus-5.initial 仍是未训练初始化，生成数据不代表已有棋力。

探索分布为 `(1-ε) Softmax(legal_logits/τ) + ε/合法动作数`，非法动作严格为 0。默认温度 1.2、epsilon 0.02；设置 `--temperature 1 --epsilon 0` 可只按原策略概率采样。

程序接口：

```python
from selfplay.generator import SelfPlayGenerator, SelfPlayRules
from training.exploration import Exploration

generator = SelfPlayGenerator.from_version(
    'Opus', 'Opus-5.initial',
    exploration=Exploration(temperature=1.2, epsilon=0.02),
    rules=SelfPlayRules(max_plies=1000), device='cpu', seed=42)
report = generator.generate(games=10, micro_batch=8, save_every=16)  # report['run_id'] 用于后续训练
```

`generate` 还接受 start_fen、prefix（动作 ID 序列）、cancel_event、progress、on_step。progress 在完整对局结束时收到完成/已保存/缓冲局数；on_step 在每次批量前向及暖启动后收到实际生成步数、推理批次数、有效并行局数，可接自定义进度展示。前缀完整重放以恢复缓存和规则历史；前缀不参与损失。CLI 对应 `--start-fen` 和 `--prefix-json 路径`，后者必须是有序动作 ID 的 JSON 数组。训练也会用当前参数重放完整前缀，不能只截取最后一个窗口的棋盘替代历史。

`micro_batch` 为同时推理的局数，必须为 2 的幂且整除 save_every；不指定时自动选不超过 16 的最大可用值。模型前向与探索概率计算在指定设备上按批处理，棋盘规则和逐局抽样在 CPU 上完成。每批结束后重建下一批缓存，每局使用独立随机数状态；提前结束的槽位以 valid=False 屏蔽，不与其他棋局混用历史。CLI 的进度、预计时长、结束时刻、吞吐和 GPU 利用率/显存占比默认每秒刷新，参数见 [指令.md](../指令.md)。

规则先判将死/困毙胜负，再判双方无进攻子力、重复局面、连续未吃子及总步数上限和棋。默认重复 3 次、连续未吃子 120 单步、总生成上限 1000 单步；红黑合计，max-plies 只统计本次新生成部分。达到上限按约定规则记录和棋；资源/取消中断时丢弃未提交批次与未完成棋局。这些是项目的训练对局规则，不实现赛事长将长捉裁决。

## 自弈 SQLite

```text
Data/dataset.sqlite3                    原古谱库
Data/SelfPlay/HaiKu/games.sqlite3        所有 HaiKu 版本的自弈数据
Data/SelfPlay/Opus/games.sqlite3         所有 Opus 版本的自弈数据
ModelParameters/HaiKu/models.sqlite3    HaiKu 参数库
ModelParameters/Opus/models.sqlite3     Opus 参数库
```

只按模型系列分库，不按版本建文件夹或文件。`--data-db` 可显式指定其他自弈库，但不能混写模型系列，也不能写入古谱库或参数库。

| 表 | 内容 |
|---|---|
| metadata | 模型系列与库结构版本 |
| runs | 每批采样的模型版本、参数 ID、权重校验值、网络配置、探索配置、规则、随机种子、价值头标记、微批量、设备 |
| games | 初始 FEN、暖启动前缀、有序新动作、结果、结束原因、最终 FEN、步数、生成序号（从 0 开始，对应 seed+序号） |
| steps | 每步走方、动作、旧 log μ、旧价值、当时温度和 epsilon |

默认每 K=16 局完整对局及其逐步记录在一个事务内提交，`--save-every` 可调整。中断时只保留已提交批次，当前不足 K 局的缓冲全部丢弃；正常完成总局数时保存最后不足 K 局的尾批。无需保存大量 8100 维 one-hot 或旧 KV 缓存；训练从初始局面与动作恢复输入。历史库若有未知结果样本，其步仍不参加终局回报损失。

## 自弈和混合训练入口

生成完成后，使用返回的 run_id 和同一个起始模型版本，替换下面的“实际run_id”。PPO 不默认读取库中全部历史版本。

```powershell
# 只训练本轮 Opus 自弈，默认权重 0/1/1/0.01
python -m training --family Opus --version "Opus-5.initial" --source selfplay --rollout-run 实际run_id --epochs 2 --batch-size 8 --micro-batch 1 --tbptt-steps 16 --device cuda

# 古谱和本轮自弈混合，显式给四个权重
python -m training --family Opus --version "Opus-5.initial" --source mixed --rollout-run 实际run_id --book-limit 128 --lambda-book 0.1 --lambda-ppo 1 --lambda-value 1 --lambda-entropy 0.01 --epochs 2 --device cuda

# HaiKu 自动关闭价值项，使用 0/1/0/0.01
python -m training --family HaiKu --version "HaiKu-5.1" --source selfplay --rollout-run 实际run_id --epochs 2 --device cuda

# 共用入口也能只训练古谱，默认 1/0/0/0
python -m training --family Opus --version "Opus-5.initial" --source books --book-limit 128 --epochs 1 --device cuda
```

`--version` 是本轮学习的起始权重，必须与 rollout-run 的采样参数 ID 和 SHA-256 一致；同一批近期数据可进行显式指定次数的 PPO 更新。下一轮请指定新训练得到的参数 ID，重新生成新对局。该入口新建 AdamW 优化器，不是原 train.py 的优化器续训入口；原 HaiKu 续训仍使用 resume_train.py。

`--T` 统一控制古谱与自弈输入：短局补零、长局裁剪；前缀计入 T 并保持完整，T 不足以容纳前缀时会报错。即使读取部分生成步，结果标签仍来自保存的完整终局。所有棋局内时间顺序保持，棋局间可打乱；每局独立缓存。训练默认微批量为 16，省略参数选择器时自动加载实际轮数最多的 ID。

`training.engine.train_logical_batch` 是共用程序接口，接收模型、优化器、多个 `TrainingBatch` 微批量和 LossWeights，预先汇总各项整批分母。默认每 16 步 backward 后 detach 缓存，整个逻辑批量只更新一次。训练时使用 eval 前向模式但保留梯度，与采样模式一致。API 的 PPO 调用还必须明确传 behavior_checkpoint_id 和 behavior_sha256，数据来源必须匹配。

训练接口可传 `progress=callback`，每个梯度截断段后回调该微批的完成比例、有效步数、微批内累计损失及分项；回调不改变损失分母或参数更新频率。返回结果另含 duration_seconds、micro_batches、micro_batches_per_second。默认 CLI 使用共用的 `training.progress.ConsoleProgress` 展示这些信息和独立刷新的 GPU 监控。

训练保存为对应模型系列库中的新参数版本，不覆盖旧权重，不自动改公开模型名称。`--set-default` 可显式更新默认指针；`--description` 添加版本说明；`--smoke` 版本不能发布到游戏。日志在 `runs/mixed/` 下，记录四项损失、有效样本数、概率比、裁剪比例、近似 KL 和更新状态，同时记录 TensorBoard 事件供中文实时窗口读取。古谱或混合训练存在独立 validation 划分时按完整验证 CE 选择本次 best，并写入 best.json；开启 --set-default 时只更新到该 best。自弈不按 PPO 损失或采样胜率选择棋力最佳；固定对手评估尚未加入。窗口与 get-best 命令见 [指令.md](../指令.md)。
